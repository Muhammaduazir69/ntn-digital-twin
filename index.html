ntn-digital-twin

ntn-digital-twin: a constellation twin that hands handover predictions to ns-3

Python digital twin for ns-3 that propagates TLEs with SGP4, predicts A3 handovers and exports a schedule that a running ns-3 simulation actuates.

What ntn-digital-twin does

ntn-digital-twin is a Python service for the ns-3 NTN toolkit that propagates satellite two-line elements with SGP4, applies an A3 handover guard, and serves the constellation state over REST, CZML and InfluxDB line protocol. It writes a handover schedule on a shared epoch that OranNtnTwinPredictionConsumer in the oran-ntn module loads and actuates inside a running ns-3 simulation.

What it models

The twin mirrors a satellite constellation and predicts handovers from ephemeris. Every loop interval it fetches TLEs from CelesTrak through a 6 h on-disk cache, or generates deterministic Walker elements on the same epoch the ns-3 scenario uses, then propagates them with SGP4 from the ntn-constellation package. It writes CZML for a Cesium viewer and ntn_sat_pos line protocol in the ntn-observability schema for InfluxDB and Grafana. A FastAPI server on port 8090 answers GET /health, GET /constellation/state and POST /predict/handover, computing elevation in closed form from ECEF to ENU on the hot path.

Handover prediction and actuation share one A3 guard, following the 3GPP TS 38.331 A3 event: a dB link-budget margin, hysteresis, time-to-trigger and a minimum service time. The guard ranks and compares on the same quantity, does not count initial acquisition as a handover, and restarts time-to-trigger when the best target changes. emit_predictions_file writes lines of t_s, ueId, recommendedGnbId and confidence, where t_s equals ns-3 simulation time. On the ns-3 side, OranNtnTwinPredictionConsumer fires a HANDOVER_TRIGGER into the E2 and CHO loop at each t_s whose confidence clears a floor. A C++ metric, CompareHandovers, replays the twin's TLEs in Sgp4MobilityModel and compares handover instants. The direction from simulator back to twin is not implemented: the twin does not ingest ns-3 state.

Measured numbers

5 handovers in 45 minutes

handovers the twin exported, at 280, 610, 1100, 1650 and 2180 s, each to a different satellite, with confidence 0.13 to 0.23

one deterministic run: Walker source, 66 satellites in 6 planes of 11 at 53 deg, observer at 33.68 N 73.05 E, 2700 s horizon, 10 s step; confidence is the elevation margin over the runner-up divided by 30 deg, clipped to [0, 1]

Each number states the run it comes from; the README of the module lists the command that reproduces it.

Install

Every module ships in the ready-built container image of the toolkit (version 3.0.1):

docker pull uzairdocker69/ns3-ntn-toolkit:latest
docker run --rm -it uzairdocker69/ns3-ntn-toolkit:latest bash

To build from source, clone ns3-ntn-toolkit, which vendors this module under contrib/, or follow the README of this repository (branch ntn-digital-twin-v4).
